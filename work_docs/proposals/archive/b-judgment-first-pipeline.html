Judgment-first memory pipeline

Pi's memory layer decides which observations survive compaction. Today that decision rests on a relevance label the observer model writes about its own output, and on a reflection citation list the reflector model writes. This demo asks one question: if a calibrated judgment is computed for every observation at the moment it is written, and code owns every threshold, floor and ordering after that, does the pipeline keep the right things? Press the buttons and watch the pool.

Throwaway prototype. Nothing here touches a network. Every TypeSafe answer is simulated and hard-coded, and every figure marked that way is invented for the demo. The drop cap curve, the drop comparator and the fold trim are faithful ports of the real functions in pi-blackhole. Token budgets are scaled down (pool 600, fold 90) so the real curves bite in a fourteen-observation pool; the shipped defaults are 20,000 for both.
